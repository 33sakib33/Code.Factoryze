# Factoryze harness preview

Factoryze uses its own agent. Connect a model from Home or Settings, then Send. Saved provider credentials are retained when the key field is left blank. Older saved settings that named another agent are migrated to Factoryze with their provider, key and budget.

In Settings → Model connection → Change, expand **Model limits and sampling** to set **Temperature**. Leave it blank for the provider default, or enter 0–2 (subject to the model's restrictions). Zero reduces sampling variation but does not guarantee identical runs. The saved setting applies to new agent sessions and every model step in that session; it does not change the optional judge. Backend configuration also accepts `FACTORYZE_TEMPERATURE`. If a model rejects sampling, Factoryze gives guidance to clear or change it and makes no automatic retry.

`packages/engine/test/harness-version.test.ts` fingerprints the instructions, protocol-owned tool definitions and the limits used by both the loop and local tools. Changing those requires a profile version bump and a new fingerprint entry; do not rewrite an existing entry. Default instructions and limits remain `factoryze@0.1.0`.

Reports show **Recorded agent settings** with each distinct recorded session configuration: harness version, model, provider host, requested temperature and OS. They are saved from session events, so restarting, changing the connection or resubmitting cannot rewrite earlier snapshots. Unset temperature is explicitly an unknown provider default. Older reports remain readable without fabricated metadata. A provider host records the configured service, not an upstream route behind an aggregator. Compare measurements only when their settings match.

Factoryze calls the authenticated task gateway directly. The engine owns the loop, provider calls, usage and budgets; the app backend executes tools and the agent pane shows streaming replies, tool rows with paths relative to the attempt, unified-diff edit approvals and command approvals. There are no background title requests or personal skill discovery.

| Tool | Preview behavior |
| --- | --- |
| `read` | UTF-8 workspace file, up to 64 KB |
| `list` | Sorted recursive file list, excluding `.git`, `.venv`, `node_modules`, `__pycache__`; up to 1,000 files / 12 levels |
| `grep` | Literal text search in those files, at most 100 matches |
| `edit` | One unique exact string replacement, reviewed in the existing diff card |
| `write` | Whole-file create/replace with a reviewed diff; up to 64 KB |
| `shell` | One-time approval, workspace cwd, task venv/package index, Bash or PowerShell; 30 seconds, bounded output |

File tools reject paths outside the workspace and symbolic links. Writes recheck the file after approval to avoid replacing a concurrent manual edit. A denied or cancelled action is not dispatched. Approved shell commands run with your OS permissions; this solo preview is not a sandbox. Shell processes receive a minimal environment, without provider keys or the gateway credential.

One prompt may make multiple model/tool steps, capped at 16 model requests. Tool output is capped at 16,000 characters. Context is guarded conservatively by byte size and the configured context/output limits: whole earlier prompt turns are dropped when necessary. An oversized active turn asks for a shorter prompt, smaller files or New session. This is bounded history, not model-generated compaction. Chat Completions and Anthropic Messages streaming are supported. Unknown, malformed or truncated tool calls never execute. Stop aborts requests, pending approvals and active shell process trees. A failed prompt closes its gateway; New session starts clean history.

Actual provider input/output/cache counts are persisted per `(user, task, workspace/run, factoryze@0.1.0, model)`. Starting a task or importing a folder/ZIP creates a fresh workspace whose meters and budget start at zero, even for the same task. New session, restart and reopening that workspace retain its counts and remaining budget. Reports keep the run's usage alongside cumulative historical totals. OpenCode's old usage stays attached to its original profile; no request or report is deleted or reattributed. Task budget overrides set the limit for each run/model without clearing any run's usage. One in-flight response can cross the limit; later requests/tool dispatches in that run are refused. Incomplete accounting blocks its own run. No dummy baseline is subtracted. Optional judge usage remains separate.

Run `pnpm test`, `pnpm typecheck`, `pnpm build:app`, build the installer, then `pnpm --filter @factoryze/app smoke:installer`. The installed smoke drives the Factoryze agent, creates a synthetic saved connection through Settings, reads a file, approves an edit and a shell command, and verifies budget refusal across New session/restart. The package verification asserts that OpenCode is absent. Test fixtures contain no real credentials or student data. Recorded three-OS smoke passes, including report pins, temperature and native-shell public tests, are linked in [the release evidence](phase-1.md#release-evidence).

Paid model calls, live spikes and benchmarks require explicit user approval and an agreed spending limit. `pnpm spike:harness:live --help` is safe to inspect without credentials or a model call. After approval, the live greeting uses backend provider environment variables or `--existing` to reuse the saved Factoryze connection through `ModelSettingsStore.forEngine()`. It uses a disposable workspace/ledger and prints only counts, not the key or model reply. A historical MiniMax-M2.7 run completed in **one request: 887 input / 9 output, 896 weighted tokens**, persisted after restart. This is connectivity evidence, not a quality benchmark; no live spike was rerun for these safeguards.
